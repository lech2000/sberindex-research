# GPU-контур исследований SberIndex

Проверено **20.09.2026** на хосте `joe`, в Incus-контейнере `aios2` и по
корпусу KB-Forge 62.

Этот текст уточняет первоначальную квитанцию corpus 62 document 12221:
название ROCm относилось к HSA-доступу в Incus; фактический backend LM Studio
установлен ниже по живому журналу и является Vulkan.

## Фактическое состояние

- GPU: AMD Radeon RX 6700 XT, `gfx1031`, 40 compute units, около 12 ГиБ VRAM.
- В `aios2` переданы `/dev/kfd`, `/dev/dri/card0` и
  `/dev/dri/renderD128`; `rocminfo` внутри контейнера видит `gfx1031` и
  `KERNEL_DISPATCH`.
- Основная LLM `gpt-oss-20b` и эмбеддер KB-Forge
  `text-embedding-bge-m3` уже делят эту карту через LM Studio. Корпус 62
  фиксирует рабочую долю выгрузки LLM `--gpu 0.85`: около 10.80 из 11.98 ГиБ
  занято и около 1.19 ГиБ оставлено эмбеддеру.
- KB-Forge обращается к эмбеддеру через отдельный мост LM Studio на порту
  3002; службы aiOS2 используют мост на порту 3001.
- Живой журнал LM Studio
  `/home/serg/.lmstudio/server-logs/2026-09/2026-09-20.1.log` называет backend
  точно: `Vulkan0 (AMD Radeon RX 6700 XT (RADV NAVI22))`. И
  `gpt-oss-20b`, и `text-embedding-bge-m3` выгружают 25/25 слоёв на Vulkan.
  При загрузке эмбеддера журнал показывал около 503 MiB свободной VRAM.

## Решение для конкурса

Табличные выборки, нормализацию, базовые статистики и Moran I выполнять на
CPU: для текущих объёмов это воспроизводимо и не вытесняет LLM/эмбеддер.
GPU использовать для модельных задач, где есть измеренный выигрыш: обучение
нейросетевого baseline, большие батчи эмбеддингов или графовые модели.

Отдельный ROCm/PyTorch worker не запускать одновременно с LM Studio без
очереди и резерва VRAM. Он должен получать эксклюзивную аренду GPU, сначала
выгружать несовместимую модель, выполнять tensor canary, записывать версию
драйвера/образа/модели и возвращать карту LM Studio. RX 6700 XT видна HSA,
но её нет в текущей официальной Linux-матрице поддерживаемых Radeon; поэтому
`rocminfo` не является доказательством работоспособности PyTorch kernels.

Действующий LM Studio/KB-Forge контур использует **Vulkan**. ROCm/HSA
проверен отдельно как доступ к устройству внутри Incus и пока не является
backend работающих моделей LM Studio.

В инфраструктуре сейчас подтверждён доступ к GPU и существующий
LM Studio/KB-Forge контур. Отдельный численный GPU-runtime считается готовым
только после умножения тензоров и эталонного расчёта на той же версии образа.
