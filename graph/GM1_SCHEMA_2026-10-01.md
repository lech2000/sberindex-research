# GM1. Доказательный временной граф муниципалитетов — схема v0.1

Дата проверки: 01.10.2026. Статус: проект контракта, не наполненная графовая БД. Исходное действие FixAR: act_5b9c0e5a4c9e4ebc в деле case_43de12a8dc2e4abd. Проверены образцы исторических расходов, населения и миграции (KB-Forge 77/15060–15061, 15067–15068, 15075–15077). Научное ревью исходного черновика: 77/15078. Этот документ исправляет отмеченные там ошибки. Выполнение запросов на графовой БД относится к GM4; отсутствие такой БД не заменяется вымышленными результатами.

## Назначение и границы

Граф связывает муниципалитеты, версии административных кодов, организации, выпуски данных, индикаторы, наблюдения и события. Он поддерживает соединение по времени и происхождению. Он не строит социальный граф пользователей и не утверждает причинность из совместного появления события и экономического ряда. Мобильность СберИндекса здесь показатель территории; это не поток МО→МО.

Исходные Parquet содержат:
- historical_spending: date, territory_id, category, value;
- population и migration: territory_id, year, period, age, gender, value.

Эти поля измерены в файлах. Все остальные поля ниже создаются при ingest или приходят из отдельного источника. Наличие значения в строке Parquet не доказывает, когда оно было опубликовано и доступно исследователю. Идентификатор territory_id нельзя выдавать за ОКТМО. Права на распространение каждого файла хранятся отдельно от его научной пригодности.

## Типы вершин и ключи

| Тип | Ключ | Существенные поля | Проверка |
|---|---|---|---|
| municipality | municipality_id | label, type, valid_from, valid_to | Внутренний стабильный ключ; имя не ключ соединения |
| administrative_identity | identity_id | municipality_id, system, code, valid_from, valid_to, source_release_id, evidence_status | system включает SBER_TERRITORY и OKTMO; код хранится строкой с ведущими нулями |
| organization | organization_id | official_registry_id?, label, municipality_id?, valid_from/to, provenance_class | Синтетическая организация отделена от зарегистрированной; связь с МО может быть unknown |
| dataset_release | release_id | publisher, source_url, retrieved_at, sha256, license_status, published_at?, available_at?, vintage?, schema_hash | Каждый новый файл/снимок — отдельный выпуск; отсутствие published_at не заменяется retrieved_at |
| indicator | indicator_id | concept, category?, unit_measure?, unit_mult?, frequency, source_url | Единица и множитель берутся из паспорта источника, не угадываются по числам |
| observation | observation_id | municipality_id, indicator_id, period_start/end, dimensions, value, obs_status, release_id, provenance_class, published_at?, available_at?, vintage?, recorded_at | Естественный ключ плюс release_id и vintage сохраняет законные ревизии |
| event | event_id | event_type, event_time, territory_scope, source_url, published_at?, available_at?, evidence_status | Событие может быть новостью или административным актом, но не объясняет показатель автоматически |

Общие поля каждой вершины и связи: source_url, checked_at, provenance_class, evidence_status, confidence, created_at. Допустимые provenance_class: observed, source_estimate, model_estimate, synthetic_assumption. Допустимые evidence_status: verified, proposed, disputed, unknown, superseded. Значение confidence без калибровки не является статистической вероятностью.

Для observation хранить dimensions как нормализованные поля category, age, gender, okved и отдельный canonical_dimension_key. Значение obs_status относится к статусу записи у источника; удаление или коррекция не уничтожает старый выпуск. Естественный ключ до версии: municipality_id, indicator_id, period_start, period_end, canonical_dimension_key. Версионный ключ добавляет release_id, vintage, obs_status. Для current-view выбирается выпуск по отдельно опубликованному правилу, а не по максимальному числу.

## Рёбра

| Тип | Откуда → Куда | Временное условие |
|---|---|---|
| HAS_IDENTITY | municipality → administrative_identity | Пересечение valid_from/valid_to |
| HAS_OBSERVATION | municipality → observation | Территория существовала в период наблюдения |
| MEASURES | observation → indicator | Версия определения индикатора подходит периоду |
| FROM_RELEASE | observation → dataset_release | release_id и sha256 совпадают |
| LOCATED_IN | organization → municipality | Только подтверждённая регистрация/адрес и даты |
| ADMIN_PARENT | municipality → municipality | Явный акт или справочник, версии границ |
| SUCCESSOR_CANDIDATE | municipality → municipality | proposed до официального акта; не использовать как автоматическое равенство |
| TEMPORALLY_ASSOCIATED_WITH | observation → event | Совпадение дат не означает causal effect |
| SPATIAL_NEIGHBOR | municipality → municipality | Метод расстояния, k, версия геометрии и вес |

Для прогнозного происхождения нужна таблица experiment_input(run_id, observation_id, role, origin_at). В роли train_feature допускаются только observed/source_estimate с известным available_at не позже origin_at. Отложенный measured_evaluation — фактическая цель, её доступность после origin ожидаема; она проверяется отдельно и никогда не подаётся модели как признак. synthetic_assumption допустима только в явно помеченной роли synthetic_control. Результаты модели — отдельные observations с provenance_class=model_estimate, не заменяют исходные.

## Время и as-of

period_start/end — время, к которому относится показатель. published_at — публикация источника; available_at — фактическая доступность исследователю; retrieved_at — скачивание файла; recorded_at — внесение в граф. valid_from/to — срок действия идентичности и связи. vintage — версия источника. Эти поля не взаимозаменяемы.

As-of(T) включает только версии, где available_at известно и не позже T, а административный код действует на T. Строки с неизвестным available_at возвращаются отдельно как not_asof_verified. Если для исторического 2024 выпуска есть только retrieved_at 2026, ретроспективный прогноз 2024 не получает эту строку в честный исторический feature-set.

## Пять проверочных запросов для будущей графовой БД

Предполагается PostgreSQL с таблицами, названными как типы выше. Интервалы полуоткрытые [valid_from, valid_to). Запросы сейчас являются исполнимым контрактом для GM4; результаты на будущей БД ещё не получены.

Q1. Конфликт одного ОКТМО у разных МО в пересекающихся интервалах:

    SELECT a.identity_id, b.identity_id, a.code
    FROM administrative_identity a
    JOIN administrative_identity b
      ON a.identity_id < b.identity_id
     AND a.system = 'OKTMO' AND b.system = 'OKTMO'
     AND a.code = b.code
     AND a.municipality_id <> b.municipality_id
     AND a.valid_from < COALESCE(b.valid_to, DATE '9999-12-31')
     AND b.valid_from < COALESCE(a.valid_to, DATE '9999-12-31')
    WHERE a.evidence_status = 'verified'
      AND b.evidence_status = 'verified';

Результат 0 строк означает отсутствие этого вида конфликта, а не полноту кроссволка. Не сравнивать только действующие коды: исторические интервалы тоже важны.

Q2. Утечка или неизвестная доступность в фактически использованном прогнозном входе:

    SELECT x.run_id, x.observation_id, x.origin_at, o.available_at
    FROM experiment_input x
    JOIN observation o ON o.observation_id = x.observation_id
    WHERE x.role = 'train_feature'
      AND (o.available_at IS NULL OR o.available_at > x.origin_at);

Для measured_evaluation требуется отдельная проверка, что цель не попала в признаки, была измерена после origin и опубликована к моменту анализа. Наличие строк в Q2 запрещает заявление об исторической as-of проверке признаков.

Q3. Дубликат внутри одной версии, без ложного отбрасывания законной ревизии:

    SELECT municipality_id, indicator_id, period_start, period_end,
           canonical_dimension_key, release_id, COALESCE(vintage, ''),
           obs_status, COUNT(*) AS n
    FROM observation
    GROUP BY municipality_id, indicator_id, period_start, period_end,
             canonical_dimension_key, release_id, COALESCE(vintage, ''), obs_status
    HAVING COUNT(*) > 1;

Два значения разных release_id/vintage — конфликт или ревизия для review, не этот вид дубликата.

Q4. Покрытие каждого выпуска по территории, месяцу и категории без заполнения нулями:

    SELECT r.release_id, o.period_start, o.canonical_dimension_key,
           COUNT(DISTINCT o.municipality_id) AS observed_municipalities,
           COUNT(*) FILTER (WHERE o.value IS NULL) AS missing_values
    FROM dataset_release r
    JOIN observation o ON o.release_id = r.release_id
    WHERE r.publisher = 'СберИндекс'
    GROUP BY r.release_id, o.period_start, o.canonical_dimension_key
    ORDER BY r.release_id, o.period_start, o.canonical_dimension_key;

Сравнить с отдельным паспортом ожидаемого множества МО для каждого выпуска; отсутствие строки не равно нулевому расходу.

Q5. Смешение синтетики с измеренной оценкой:

    SELECT x.run_id, x.observation_id, o.provenance_class, x.role
    FROM experiment_input x
    JOIN observation o ON o.observation_id = x.observation_id
    WHERE (x.role = 'measured_evaluation'
           AND o.provenance_class NOT IN ('observed', 'source_estimate'))
       OR (x.role = 'synthetic_control'
           AND o.provenance_class <> 'synthetic_assumption');

Синтетические наблюдения допустимы в графе, но не в измеренном holdout. Этот запрос проверяет границу, а не запрещает синтетику.

## Приёмка GM1 и переход

GM1 можно закрыть после ревью версии схемы, проверки пяти запросов на тестовой схеме и фиксации известных неизвестных полей. Текущий артефакт закрывает проектирование, но SQL ещё не выполнялся на графовой БД. GM2 строит версионированный territory_id↔ОКТМО с конфликтами и unknown successor. GM3 загружает выпускаемые наблюдения, GM4 исполняет проверки и сравнивает выпуски. Ни один из этих шагов не повышает синтетическую гипотезу до факта.
