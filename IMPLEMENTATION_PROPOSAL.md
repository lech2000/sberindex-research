# Реализация исследовательского контура

Версия 20.09.2026. Цель — превратить два каркаса в воспроизводимые исследования; лендинги остаются шаблонами до появления зафиксированных метрик.

## Архитектура

`ingest` сохраняет неизменённые ответы и файлы в `data/raw/<source>/<vintage>/`. `normalize` приводит поля и единицы, но никогда не перезаписывает raw. `identity` строит версионный Sber ID ↔ ОКТМО crosswalk. `quality` выпускает схемы, покрытие, дубликаты и пропуски. `feature_store` создаёт проектные таблицы с `observed_at`, `published_at`, `available_at`, `vintage` и lineage. Модули `atlas` и `radar` читают только зафиксированные витрины. `evaluation` формирует машинные метрики и таблицы для отчёта. `export` заполняет шаблоны лендингов только существующими артефактами запуска.

Каждый run получает каталог `runs/<run_id>/` с `config.yaml`, git revision, входными SHA-256, seed, временем, средой, метриками и списком выходов. `latest` не является источником истины: отчёт ссылается на конкретный `run_id`.

## Порядок разработки

1. Реализовать единый загрузчик с conditional GET, retry/backoff, content type/size guard, атомарной записью и SHA-256. Отдельные адаптеры: SberIndex, Rosstat/BDMO, CBR, calendar, Copernicus и news metadata.
2. Реализовать `source_registry.parquet` и `source-queue.json` как журнал доступности. Агент может предложить URL и разобрать публичную страницу, но статус `verified` ставит только валидатор файла.
3. Закрыть P0-кроссволк и занятость. До этого Atlas запускается только на однозначном пересечении, Radar — без территориальных погодных и новостных признаков.
4. Собрать `panel_v1` и общий evaluator. Для Atlas сначала A4; для Radar сначала R2. Эти два прогона дают рабочие вертикальные срезы и выявляют ошибки данных раньше сложных моделей.
5. Добавлять по одному усложнению с абляцией: граф/время у Atlas, бустинг/TSFM/события у Radar. Любое усложнение без сравнения на общей выборке отклоняется.
6. После заморозки метрик собрать русские отчёты и подставить экспорт в лендинги. Плейсхолдеры с фиктивными числами запрещены.

## Работа агентов

Оба дела маршрутизируются на специализированные доменные агенты. На каждом ходе агент читает текущий этап из приложенного плана, проверяет его входы, выполняет не более одного логического шага и пишет конкретный результат в дело. Публичный поиск не считается доказательством до сохранения источника и паспорта.

Основной актуальный поиск выполняет `mimo-v2.5-pro`. Apify включён только как платная эскалация сложного разбора: один закреплённый `apify/rag-web-browser` build `1.0.28`, до 5 результатов, provider cap $0,25. Списание — фактическая стоимость ×2 по версии тарифа `apify_run_x2_v1`, максимум 475 кредитов, идемпотентно по run ID. Без выделенного токена инструмент виден как не настроенный и не запускает Actor.

recon-mcp подключён через отдельный MCP-клиент. Агент видит allowlist и пять пассивных операций; сервер повторно проверяет цель. Официальные домены СберИндекса и Росстата не добавляются в security-recon allowlist ради загрузки данных: для них используются официальный файл/API, Jina/robots-aware адаптер или ручной handoff.

## Приёмка первой реализации

- конфигурация пакета валидируется схемой `DomainPack`;
- шлюз выдаёт каждому агенту ровно его allowlist;
- платные инструменты скрыты без доверенного `principal_id` и получают его только из HTTP-заголовка диалога;
- token Apify и token recon-mcp находятся в разных read-only secret-файлах и не попадают в общий env;
- тестовый вызов `recon_mcp_allowlist` проходит из tool-service;
- Apify health показывает `configured=true`; предметный run `Kn5Qc9K1OmV3DsXgn` выполнен через агентский MCP, вернул 3 кандидата и идемпотентно списал 11 кредитов;
- оба дела читают правильную версию агента и имеют приложенную собственную лестницу;
- документы проиндексированы в корпусах 74/75/76, тяжёлые данные представлены паспортами и SHA-256;
- `check_scaffold.py`, unit-тесты инструментов, валидация миграций и проверка живых маршрутов проходят.

## Ближайший исполнимый срез

P0: справочник СберИндекса, ОКТМО, показатель БДМО 8423005 и crosswalk. Затем в течение одного вертикального прохода выпустить `panel_v1`, Atlas A4 и Radar R2. Погода и новости идут после этого: они могут улучшить Radar, но не должны задерживать доказуемые baseline и аудит утечек.
