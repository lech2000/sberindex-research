## A6 — 2024 holdout и проверка экономической интерпретации

Исследователь Atlas должен зафиксировать до нового прогона проверяемые
тезисы: (1) какая доля сопоставлений сохраняется при M±25% на отложенном
2024; (2) отделяются ли синтетические события рождения, исчезновения и
стабильности при заданном false-match budget; (3) имеет ли месячная группа
внешнюю экономическую связь после контроля размера и региона.

F7b готовит ограниченный воспроизводимый расчёт с входами
`economic-atlas/data/panel_v1.parquet`, `runs/A6_v2/{assignments.parquet,
calibration.json}`, `4_bdmo_salary.parquet`, `2_bdmo_population.parquet`,
`municipal_dictionary.parquet`. Использовать существующие функции
`build_monthly_shares`, `standardize_frozen`, `track_identities` без
перекалибровки на 2024. Сохранить помесячные таблицы `best`, `second`,
`best−second`, status, identity ID и флаг неоднозначности для базового
M и M±25%, плюс числитель/знаменатель каждой доли. Отдельные синтетические
положительные/отрицательные миры должны иметь известные истинные метки;
реальные `birth` сами по себе истинными метками не считаются.

Внешний тест: зарплата «Все отрасли», годовая 2024, без скрытой замены
`NaN` на ноль; конфликтующие непустые дубликаты приводят к отказу. Отчёт
показывает покрытие по группам и две заранее оговорённые спецификации:
`log(salary24) ~ group + log(pop24) + region FE` и та же формула с
`log(salary23)`. Bootstrap по регионам. Повторить при M±25% только для
устойчиво опознанных групп, отдельно от всех месячных меток; если таких
групп нет, честно вывести `NA`.

Выход: `economic-atlas/runs/A6_science_review/` с машиночитаемыми
таблицами, `metrics.json`, `manifest.json` (SHA файлов/кода, версии, seed,
команда), русским README и негативными результатами. Критерий приёмки:
базовый M точно воспроизводит архив; 2023 не попадает в holdout-оценку;
синтетический контроль различает ошибку и истинное событие; экономические
выводы не приписаны `ambiguous` identity. Если критерий не проходит,
опубликовать ограничение и оставить A6 OPEN.

## R8 — парное сравнение TSFM, time-as-of и контроли

Исследователь Radar фиксирует целевой тезис до выбора модели: выигрыш
прогноза против `lastavailable` на общей маске, отдельно по горизонту,
категории и целевому месяцу. Выигрыш Prophet по МО устойчив условно,
но bootstrap по шести месяцам включает ноль; сильный декабрьский вклад
нельзя скрывать в общем MAE.

F7b готовит только расчётный код и конфиг для воспроизводимого, возобновляемого
TSFM-прогона на **той же 171150-точечной маске** из
`shock-radar/runs/R8_prophet_full_20260927/predictions.parquet`.
Использовать те же `origin`, `target`, `horizon`, `territory_id`, `category`,
двухмесячное правило доступа и evaluator. Сохранить точные ревизии весов,
версии библиотек, устройство (Mac MPS/GPU либо CPU), время, чекпоинты и
отказы. Старые агрегаты `R4/metrics.json` без индивидуальных прогнозов
не считать парным сравнением; R3 с известной утечкой исключить из выбора.

Параллельно проверить 22 флага качества новостей с URL, published_at,
first_seen_at и архивным available_at, если он существует. Пока допустимых
исторических новостей `0/64`, news-only и news-effect равны `NA`;
запрещено превращать их в нулевой эффект. Обязательные контроли:
изменение будущих входов не меняет прошлый прогноз; перестановка target;
ложные события; lag 1/2/3 месяца как анализ чувствительности, причём
основной 2-месячный lag назван **допущением** до подтверждения источником.

Выход: `shock-radar/runs/R8_science_review/` с парными прогнозами,
таблицами MAE и контролей, временными интервалами, `manifest.json`,
README и журналом ошибок. Закрывать R8 можно только после независимой
сверки артефактов и удаления любых неподтверждённых утверждений об
историческом as-of или раннем предупреждении. R9 не открывать раньше.
