# F03: прежние метрики R3 исключены из доказательств качества

Проверено 26.09.2026: чтение `shock-radar/src/f03_global_boosting.py` в репозитории lech2000/sberindex-research (main 070731d), сопоставление с `shock-radar/runs/R3/metrics.json`.

В `run()` строки одного forecast origin передаются в `model.fit(X[feat_cols], y)`, затем в `model.predict(X[feat_cols])`; y состоит из расходов прогнозируемого месяца. Это оценка на обучающих целевых строках, а не прогноз вне обучающего окна. `LAG_RELEASE=2` объявлен, но при построении признаков не применяется: берётся `ym < origin`. Поэтому MAE R3 (199.39 / 234.02 / 263.64) и сравнение с last_value нельзя использовать как доказательство качества прогноза. Наличие исторических лагов в X не устраняет утечку целевых y.

Архив R3 сохраняется для воспроизводимости ошибки. Его статус в текущем исследовании: INVALID_TARGET_LEAKAGE, не валидный forecasting baseline. R8_v2 должен обучаться на примерах, чьи целевые расходы уже доступны к forecast origin с принятым консервативным лагом 2 месяца; оценивать на отдельных будущих target строках. Лаг публикации остаётся предположением, не измеренным vintage. Нужны парные маски, prefix-invariance и отрицательные контроли. Исправление научного кода запущено через F7b fixar-devops 26.09.2026, результат пока не проверен. Запись аудита: корпус76/13864; уточнение о неподтверждённых датах публикации:76/13868 и77/13869.

Это не утверждение об ухудшении экономики или невозможности прогнозирования. Подтверждена ошибка протокола оценки конкретного файла.
