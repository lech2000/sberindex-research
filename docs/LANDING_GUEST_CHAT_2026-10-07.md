# Один гостевой ответ перед регистрацией в Фиксаре

На лендингах Атласа и Радара посетитель получает один ответ по опубликованным исследованиям без регистрации. Следующий содержательный запрос предлагает зарегистрироваться в Фиксаре для углублённого чата и подачи заявки на доступ к проектам и материалам дел. Права на закрытые материалы предоставляются отдельно после рассмотрения заявки.

Лендинг открывает гостевую сессию с существующей служебной cookie Фиксара. После перезагрузки страницы и перехода между двумя лендингами гостевой лимит сохраняется на сервере. Первое резервирование атомарно занимает единственное место; повторный запрос возвращает приглашение без нового вызова платной модели. Новый токен не сохраняется в JavaScript. Посетитель видит пояснение о служебной cookie и одном ответе до отправки вопроса.

Гостю доступны только проверенные опубликованные источники. Загрузка файлов и дальнейший чат требуют подтверждённого входа. При сбое после резервирования место не возвращается: это защищает от двойной оплаты при неизвестном результате первого вызова. Очистка cookie создаёт другую гостевую сессию; прежние общие ограничения частоты на платформе продолжают действовать.

Проверено 07.10.2026: шесть сценариев `node --test tests/landing_guest_chat.test.cjs` проверяют новый визит, повторный вопрос без POST, перезагрузку и переход между проектами, непринятую cookie, запрет гостевой загрузки файлов, продолжение чата после входа и восстановление действующей cookie при устаревшем токене прежнего интерфейса. В aiOS 204 серверные проверки прошли; конкурентный тест принимает одно из двадцати резервирований. Подмена клиентом личности и второй прямой запрос также проверены. После совмещения с текущей версией dialog-service другой сессии связанный набор со справочником API завершился 203 passed; дополнительный набор квоты и каталога API — 42 passed.

Выложено 07.10.2026 под `deploy_lock.sh`: aiOS `6186494c85e290a1c84521340b3d6d39defd0239`, интерфейс из GitHub main `ebc417571e1e4e90ecc7af2ef5f02bde2a41d880`. В новых образах совпали SHA всех 125 исходных файлов public-gateway и 127 файлов dialog-service. Пересозданы эти две службы; 26 остальных работающих контейнеров сохранили ID. Конфигурация модели и приостановленный платный CMD-аудит сохранены.

Живая проверка через HTTPS API с отдельной cookie в памяти: первый запрос получил HTTP 200, ответ `gigachat-sber-max` и три опубликованных источника; второй запрос по другому проекту получил HTTP 200 с приглашением в регистрацию. Журнал модели до первого запроса был пуст; после него появилась одна успешная платная операция. Две попытки MiMo были заблокированы действующим правилом юрисдикции до обращения к провайдеру и имеют нулевые токены. После второго запроса журнал не изменился. Частный чат гостю вернул 403; выбор модели клиентом — 422 без расходования места. Подробнее: [квитанция живой проверки](evidence/landing-guest-chat-20261007/live-check.json).

Сверены три опубликованных файла: общий JS и два HTML лендинга, все HTTP 200 и SHA совпадают с источником. Научные отчёты этим выпуском не обновлялись. Полный валидатор после выкладки завершился PASS, 41/48 проверок, семь прежних предупреждений об остановленных riskproof/n8n и закрытой OpenAPI tool-service.
