## Найден и исправлен дефект tracker

В `track_identities` ветви `birth` и `birth_candidate` записывали буквальный
статус в назначения/события, но не обновляли переменную для таблицы областей.
Первый новый кластер мог вызвать `UnboundLocalError`; поздние рождения
получали в таблице областей предыдущий статус, например `continuing`.

Исправление — явное присваивание статуса в двух ветвях. Формулы, пороги,
центры и правила сопоставления не изменены. Минимальный контрпример
воспроизвёл ошибку; новые проверки первого рождения и первого кандидата
прошли. Во всех 210 повторных конфигурациях статус области совпадает со
статусом её назначений. Существующие self-check tracker также прошли.

Первый запуск сохранён отдельно для аудита и не служит источником
итоговых ошибок узнавания. По всем 210 конфигурациям до/после патча
совпали выбранные K, числа M3-кандидатов и числа сопоставленных событий.
Исправились статусы и основанный на них расчёт ошибок узнавания.
Исторические A6-артефакты не перезаписаны.

## Как читать ошибки и интервалы

FPR=FP/(FP+TN) относится только к фиксированному пространству известных
пар «текущий истинный субъект × допустимая предыдущая истинная идентичность».
Сопоставления с неопознанной/нечистой идентичностью показаны отдельно.
В общей консервативной доле неподтверждённых сопоставлений они учтены
как ошибки; это не доказательство ложности каждого такого сопоставления.
Пропуск узнавания FN/(TP+FN) включает воздержания при истинном совпадении.
`ambiguous` и `birth_candidate` не считаются принятым решением.

Метрика событий — FDR=FP/(TP+FP), **не FPR**. Универсум TN для событий
не задан, поэтому event FPR не придуман. Matching требует точного месяца,
типа, субъекта, состава родителей/детей; повторное предсказание считается FP.
Субъект сопоставляется при ≥0,8 чистоты и ≥0,8 покрытия истинной группы.
Предсказанный ID связывается с истиной однократно при первом появлении,
поздние фрагменты нельзя переименовать в верный результат.

Новые компоненты split/merge считаются рождениями идентичностей;
предшественники исчезают после четырёх пропусков. Это заранее заданная
структурная онтология, а не утверждение о рождениях экономических типов.
При основном M есть два кластера, не достигших порога сопоставления
с истинным субъектом; oracle таких кластеров не имеет. Их число при
сравнении M неизменно, поскольку кластеризация переиспользуется.

95% интервалы из `metrics.json` используют 10 000 bootstrap повторов
пяти seed-блоков; месяцы и пары внутри них не объявлены независимыми.
Для основной event FDR/FNR интервал [0%; 6%]. Пять seed — мало;
нулевые/вырожденные интервалы на простых мирах не доказывают нулевую
ошибку в популяции. Выбор M=0,75 по красивой таблице был бы подбором
на уже просмотренных данных, поэтому в рабочую методику он не переносится.

## Воспроизведение

Используется среда `requirements-integration.txt`, Python 3.13.0.
Из корня репозитория:

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv-integration/bin/python \
  economic-atlas/src/a6_frozen_controls.py --self-check \
  --atlas-src economic-atlas/src

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv-integration/bin/python \
  economic-atlas/src/a6_identities.py --self-check

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv-integration/bin/python \
  economic-atlas/src/a6_frozen_controls.py \
  --atlas-src economic-atlas/src \
  --calibration economic-atlas/runs/A6_v2/calibration.json \
  --out output/a6-frozen-controls
```

Требуется новый `--out`. Публичный run содержит protocol, metrics,
таблицы по конфигурациям, месяцам и событиям; все строки синтетические.
Служебные квитанции и первый ошибочный запуск хранятся отдельно.
Следующий шаг — научная оценка критериев/ограничений A6 и сводка.
