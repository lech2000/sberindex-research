# Сезонность категории: проверка гипотезы на точной маске R9

Уточнение04.10: [сводка результатов, пороговая проверка и оба сезонных окна](../../../docs/ATF_FINDINGS_AND_CLOSEOUT_2026-10-04.md). Описательные метрики не означают приёмку научных ворот.


Проверено 03.10.2026 фактическим полным расчётом на Mac. На трёх коротких горизонтах сохранены все 220 962 строки исходной маски R9: исключений нет. Формула и параметры зафиксированы в protocol.json до полного расчёта, однако целевое окно уже просматривалось автором гипотезы: это exploratory audit, не независимый тест.

Формула: `forecast(i,c,t+h) = y(i,c,t) × median_c(t+h−12) / median_c(t−12)`. Медианы — все наблюдаемые МО категории в соответствующем прошлом месяце. Последнее значение строго совпадает с origin из R9; оба месяца отношения ≤ origin. Пропуски и нулевой знаменатель не заменяются числом.

## Что можно утверждать

На этом ретроспективном окне совместная сезонная информация категорий существенно снижает ошибку относительно сохранённых несезонного Prophet и last-value. Это первый явный положительный прогнозный результат проекта. Он опирается на один год сезонного образца (2023). Сохранённый Prophet использует линейный тренд и отключённую годовую сезонность; превосходство над Prophet с правильно заданной сезонностью или над всеми современными моделями не показано. Групповой прогноз использует общий прошлый сигнал, а Prophet здесь обучен отдельно на ряду.

R9 использует train-through-origin без публикационного лага. Никакие значения после origin не входят в формулу; это проверено mutation/append fixtures. Исторические available_at/vintage не подтверждены. `scientific_pass=false`, `independent_new_holdout=false`, `historical_asof_verified=false`.

## Воспроизведение

Зависимости: `requirements-integration.txt`; из корня репозитория:

```bash
python shock-radar/src/r9_category_seasonal.py --self-check
python shock-radar/src/r9_category_seasonal.py --raw <frozen-8_consumption.parquet> --predictions <audited-R9-predictions.parquet> --outdir <NEW-run-directory>
```

Загрузчик требует точные SHA входов из protocol.json, проверяет значения actual/origin по raw и число строк каждого горизонта. Идентификаторы, actual и прогнозы хранятся локально в новом Parquet; публично доступны агрегаты и код. Ни один Prophet fit повторно не запускался. Два исходных SHA и SHA кода/выхода — в metrics.json.
